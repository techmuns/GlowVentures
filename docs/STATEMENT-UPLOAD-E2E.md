# Statement upload rehearsal

`npm run test:statement-upload` starts a complete isolated local rehearsal. On
this Mac, run it through `codex-heavy-run -- npm run test:statement-upload`.
It exports the exact Git revision to the checkout's ignored `.cache/build-copies/`
and reuses prepared dependencies. A previous rehearsal is retained, not overwritten.
CI runs the same check on Linux and saves its logs, JSON evidence and screenshots.

The fixture withdraws seven **unmodified original PDF statements** from an isolated
baseline, covering the two HDFC Balanced Advantage folios and three Motilal demat
accounts holding ICICI India Opportunities units. It drops a directory of these
actual bytes onto the real Statement Library control, including paginated directory
entries. The real Pages handler writes blobs and a batch commit to a local bare Git
inbox. The real intake CLI performs classification, extraction, identity/coverage and
reconciliation checks, book generation and its required financial/build gates.

The test verifies that neither the served version nor the staged source bytes change
prematurely. A candidate is re-extracted and regenerated byte-identically. Pending
CI, unavailable review and the interval between a reviewed merge and deployment
all retain the original inbox bytes. Publication confirmation checks the exact
normalized document versions. Only then does the inbox report `landed`.

An already-open member-scoped dashboard picks up the new version automatically.
All five MF rows must match their source account, security, units, cost, value and
purchase date. Data Audit must expose those same account/unit/date facts even where
its statement has no valuation. The broad investment-date browser regression then
checks every holdings-table family, nested views, sorting, saved layouts, member
scope, totals and mobile. Absence of a source valuation remains absent.

**Service boundaries:** GitHub REST/CLI, CI/reviewer callbacks and Pages activation
are emulated against local Git and a loopback HTTP server. Extraction, reconciliation,
book generation, the real upload handler/client, inbox persistence, intake runner,
publication/version checks and browser tables are not replaced with mock results.
The external review-success callback is a test fixture, not a claim of automated
review approval. The test explicitly exercises review unavailability before it.
External market feeds are disabled and the existing verified symbol mappings stand.

No production upload, deployment, data change or workflow dispatch occurs. A successful
local rehearsal proves the code path and data propagation. Live GitHub token scopes,
review-service availability and production dispatch still need their own deployment
configuration; a missing gate must hold publication rather than claim success.
