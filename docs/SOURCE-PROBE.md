# Source probe — what each remaining data source would cost to wire

Generated by `npm run probe:sources` (`scripts/harvest/probe-sources.mjs`), run on
a **GitHub Actions runner**. Nineteen sources stand between the dashboard and
roughly 60 checklist requirements. This records what was measured, not what the
documentation claims.

**Why this exists.** Every source below is "published monthly by a ministry",
and that sentence has already been wrong twice in this repo in opposite
directions: data.gov.in looked live — a fresh `updated` timestamp every day —
and its data stopped in 2023; FRED was declared permanently unreachable and
answers in under a second from the machine that actually runs the harvest.

**What it decides.** Whether the data sits behind a SPREADSHEET (a day), a PDF
(a reader, several days), a JS PORTAL (an API to reverse-engineer), or a LOGIN
(a commercial licence, not engineering at all). Those four lead to completely
different plans and no amount of reading documentation separates them reliably.

---

## The finding that changes the plan

**Seven sources refuse connections from BOTH the development container and the
GitHub Actions runner** — MoSPI (CPI and IIP), Vahan, Indian Railways, the
Indian Ports Association, the Ministry of Coal and the Joint Plant Committee.
The failures are `ERR_CONNECTION_RESET`, `ERR_CONNECTION_REFUSED` and hard
timeouts, not 404s or empty pages.

Both of those environments are **outside India**. GitHub's hosted runners are US
and EU infrastructure, and it is common for Indian government sites to refuse or
silently drop foreign traffic. So the honest reading is:

> These sources failed from two foreign networks. That is **not** the same as
> "unreachable", and they must not be written off on it — that is exactly the
> mistake FRED cost us, one level up.

Confirming or refuting this needs one request from an Indian IP. If the
hypothesis holds, those seven sources — **14 checklist items**, including the
current CPI and IIP readings that data.gov.in cannot serve — need either a
self-hosted runner in India or a small fetch relay there. That is an
infrastructure decision, not a reader-writing one, and it should be taken before
any of the seven is scheduled.

## Worklist, easiest first

### Spreadsheets — the cheap case (11 items)

| Source | Items | Unblocks | Evidence |
| --- | ---: | --- | --- |
| AMFI monthly | 8 | MF flows, SIP flows, folios, ETF flows | 100 `.xls` links; `amjul2026repo.xls` is current |
| NSDL investor statistics | 2 | Demat accounts, active trading accounts | 3 spreadsheet links — verify they are the right table before building |
| CEA renewable generation | 1 | Renewable generation, cross-check on the capacity series | `RE_Monthly_Generation_report_June_2026.xlsx` |

AMFI's workbooks are legacy BIFF `.xls`, which neither ExcelJS nor this repo's
`sheet.mjs` opens — you have said you will wire these from the other dashboard
that already parses them, which avoids adding a BIFF reader here.

### PDF only — one reader each (24 items)

| Source | Items | Unblocks |
| --- | ---: | --- |
| **RBI Weekly Statistical Supplement** | **13** | Credit growth by bank type AND by sector (11), money supply, liquidity |
| RBI Handbook of Statistics | 4 | Household financial savings, physical savings, household debt/GDP, asset mix |

The RBI Weekly Statistical Supplement is **the best ratio in the entire
backlog**: thirteen requirements from one reader. It should be the first PDF
reader written.

NHB RESIDEX was a 404 locally and resolved on the runner once loaded in a
browser — a source recovered purely by measuring twice.

### JS portals — the data is behind XHR, not links (17 items)

| Source | Items | What the browser saw |
| --- | ---: | --- |
| RBI DBIE | 13 | page renders, no file links — DBIE serves data through its own API |
| GST portal | 2 | 205 links, no files |
| Controller General of Accounts | 2 | 307 links, no files |

These are not dead. A portal that renders a table is fetching it from somewhere,
and that endpoint is usually stable and JSON. Each needs its network traffic
inspected once. DBIE in particular would be a **second route to the same 13
items** the RBI supplement carries, and a far better one if its API is open —
worth checking before committing to the PDF reader.

### Geo-blocked, probably (14 items)

MoSPI CPI (4), Vahan (4), Indian Railways (2), MoSPI IIP (1), Indian Ports
Association (1), Ministry of Coal (1), Joint Plant Committee (1). See the
finding above. **Not written off.**

### Gated — a licence, not engineering (2 items)

NSE market turnover: 41 login and subscription markers, no data links. Exchange
volumes and F&O turnover need a commercial arrangement.

## Corrections this probe needed before it could be trusted

Recorded because they are the argument for running it at all:

- `/monthly-generation-report/` was a guess and 404s. CEA publishes generation
  and PLF in its monthly **executive summary**, and renewable generation
  separately **as a spreadsheet**.
- The sample link printed under each verdict was whichever dated URL sorted
  first, regardless of type — so AMFI was correctly classified SPREADSHEET on
  100 `.xls` links while displaying a PDF beneath it, reading as a
  contradiction. Samples now match the verdict they illustrate.
- Five sources return HTTP 200 with an empty shell because they build their page
  with script. Classifying those "no data links" from a `fetch` would write off
  five sources on a limitation of the probe rather than of the source, so
  anything a fetch cannot read now gets a second pass in a real browser.

## Recommended order

1. **Settle the geo-block question** — one request from an Indian IP. It governs
   14 items and an infrastructure decision.
2. **Inspect RBI DBIE's API** — half a day, and it may close 13 items far more
   cheaply than the PDF reader.
3. **NSDL and CEA renewable** — spreadsheets, a day between them, 3 items.
4. **RBI Weekly Statistical Supplement reader** — 13 items, the best ratio here,
   unless step 2 supersedes it.
5. **RBI Handbook, NHB RESIDEX, CEA executive summary, DGCA, PPAC** — one reader
   each, 11 items between them.
6. **NSE** — put in front of the family as a cost, not a task.
